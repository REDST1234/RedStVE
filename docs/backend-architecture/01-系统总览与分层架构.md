# 批次 1：系统总览与分层架构

## 1.1 系统定位

后端作为"爆款结构迁移引擎"的核心服务层，承担以下职责：
- 接收样例视频，调用 FFmpeg + LLM 完成结构拆解
- 管理通用模板与品类知识库
- 识别素材缺口并提供补全策略
- 基于模板编排新视频结构，输出给前端展示

## 1.4 异步任务处理架构

视频拆解是耗时操作（FFmpeg 处理 + 多轮 LLM 调用），需要异步处理。

```
前端上传视频 ──► Controller 接收
                     │
                     ▼ 同步返回 taskId
              Service 创建任务 ──► 发送消息到 RabbitMQ
                                       │
                                       ▼
                              Consumer 消费消息
                                       │
                    ┌──────────────────┼──────────────────┐
                    ▼                  ▼                  ▼
              FFmpeg 抽帧        FFmpeg 镜头切分      ASR 转文字
                    │                  │                  │
                    └──────────────────┼──────────────────┘
                                       ▼
                              LLM 结构分析（可能多轮）
                                       │
                                       ▼
                              写入结果 + 更新任务状态
                                       │
                                       ▼
                        前端通过 SSE/轮询 获取进度与结果
```

**RabbitMQ 队列设计：**

| 队列名 | 用途 | 消费者 |
|--------|------|--------|
| `video.analysis.queue` | 视频拆解任务 | VideoAnalysisConsumer |
| `material.process.queue` | 素材预处理任务 | MaterialProcessConsumer |
| `migration.compose.queue` | 结构迁移编排任务 | MigrationComposeConsumer |

**任务状态流转：**
```
PENDING → PROCESSING → ANALYZING → COMPLETED
                    ↘ FAILED
```

> [!NOTE]
> 每个阶段通过 Redis 存储任务进度百分比和当前步骤描述，前端可实时查询。

## 1.5 统一响应与异常约定

**统一响应结构：**
```json
{
  "code": 200,
  "message": "success",
  "data": { },
  "timestamp": 1716220000000
}
```

**异常分级：**
- `400` 参数校验失败（如视频格式不支持）
- `404` 资源不存在（如模板/任务 ID 不存在）
- `422` 业务逻辑异常（如素材不足无法迁移）
- `500` 系统内部错误（FFmpeg 崩溃、LLM 超时等）
- `503` 服务繁忙（队列积压）

## 1.6 技术扩展点

> [!TIP]
> 以下设计点为开发预留了灵活空间，开发者可根据实际情况选择实现策略。

1. **Engine 可插拔**：每个 Engine 定义接口，便于后续替换实现（如换 LLM 供应商）
2. **消息队列可降级**：开发阶段可通过 `@Async` 线程池替代 RabbitMQ，降低本地开发门槛
3. **文件存储可升级**：当前本地 `/data`，后续可无缝切换到 OSS，只需替换 Infrastructure 层实现
4. **LLM 调用链可观测**：建议在 LlmClient 中埋入日志，记录每次 prompt/response 便于调试
