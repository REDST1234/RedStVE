# 批次 1：系统总览与分层架构

## 1.1 系统定位

后端作为"爆款结构迁移引擎"的核心服务层，承担以下职责：
- 接收样例视频，调用 FFmpeg + LLM 完成结构拆解
- 管理通用模板与品类知识库
- 识别素材缺口并提供补全策略
- 基于模板编排新视频结构，输出给前端展示

## 1.2 整体分层架构

```
┌─────────────────────────────────────────────────────┐
│                   Frontend (React)                  │
└──────────────────────┬──────────────────────────────┘
                       │ REST API / SSE
┌──────────────────────▼──────────────────────────────┐
│              Controller 层（接口网关）                │
│  接收请求、参数校验、返回统一响应                      │
├─────────────────────────────────────────────────────┤
│              Service 层（业务编排）                   │
│  编排多个 Engine 的调用顺序，管理业务状态              │
├─────────────────────────────────────────────────────┤
│              Engine 层（能力引擎）                    │
│  ┌───────────┐ ┌───────────┐ ┌───────────────────┐  │
│  │ FFmpeg    │ │ LLM       │ │ TemplateEngine   │  │
│  │ Engine    │ │ Engine    │ │ (模板引擎)        │  │
│  └───────────┘ └───────────┘ └───────────────────┘  │
│  ┌───────────┐ ┌───────────┐ ┌───────────────────┐  │
│  │ ASR       │ │ Material  │ │ MigrationEngine  │  │
│  │ Engine    │ │ Engine    │ │ (迁移引擎)        │  │
│  └───────────┘ └───────────┘ └───────────────────┘  │
├─────────────────────────────────────────────────────┤
│           Infrastructure 层（基础设施）               │
│ 文件存储(/data) │ Redis缓存 │ DB(MySQL) │ Chroma │ Ollama │
└─────────────────────────────────────────────────────┘
```

## 1.3 后端包结构规划（领域分包 + 引擎解耦）

```
com.bytedance.aivideo
├── video/                      # 视频拆解域（controller/service/entity/mapper/dto）
├── deconstruct/                # 拆解项目域（controller/service/entity/mapper/dto）
├── engine/                     # 能力引擎层（可插拔）
│   ├── ffmpeg/
│   │   ├── api/                # 引擎接口（如 MediaProbeEngine）
│   │   ├── model/              # 引擎模型（如 MediaProbeResult）
│   │   └── local/              # 本地实现（ProcessBuilder 调 ffprobe）
│   ├── llm/
│   ├── asr/
│   ├── template/
│   └── migration/
├── config/                     # 配置类（Redis/MQ/MyBatis/EngineProperties）
├── common/                     # 公共能力（api/error/exception/handler/entity/util）
└── infrastructure/             # 文件存储、MQ、缓存、外部客户端适配（预留）
```

> [!NOTE]
> 业务域（`video/deconstruct`）只依赖引擎接口（`engine.*.api`），不直接依赖具体实现（`engine.*.local`），避免 `ProcessBuilder`、命令参数、解析细节渗透到业务编排层。

## 1.4 异步任务处理架构

视频拆解是耗时操作（FFmpeg 处理 + 多轮 LLM 调用），需要异步处理。

```
前端上传视频 ──► Controller 接收
                     │
                     ▼ 同步返回 taskId
              Service 创建任务 ──► 发送消息到 RabbitMQ
                                       │
                                       ▼
                              Consumer 消费消息
                                       │
                    ┌──────────────────┼──────────────────┐
                    ▼                  ▼                  ▼
              FFmpeg 抽帧        FFmpeg 镜头切分      ASR 转文字
                    │                  │                  │
                    └──────────────────┼──────────────────┘
                                       ▼
                              LLM 结构分析（可能多轮）
                                       │
                                       ▼
                              写入结果 + 更新任务状态
                                       │
                                       ▼
                        前端通过 SSE/轮询 获取进度与结果
```

**RabbitMQ 队列设计：**

| 队列名 | 用途 | 消费者 |
|--------|------|--------|
| `video.analysis.queue` | 视频拆解任务 | VideoAnalysisConsumer |
| `material.process.queue` | 素材预处理任务 | MaterialProcessConsumer |
| `migration.compose.queue` | 结构迁移编排任务 | MigrationComposeConsumer |

**当前交换机与路由契约（已在 `RabbitMQConfig` 定义）：**

| Exchange | Type | Routing Key | Queue |
|----------|------|-------------|-------|
| `aivideo.task.exchange` | direct | `video.analysis` | `video.analysis.queue` |
| `aivideo.task.exchange` | direct | `material.process` | `material.process.queue` |
| `aivideo.task.exchange` | direct | `migration.compose` | `migration.compose.queue` |

**任务状态流转：**
```
PENDING → PROCESSING → ANALYZING → COMPLETED
   │              │            │         │
   │              │            │         └→ DELETE（历史删除）
   │              │            │
   │              │            └──────────→ FAILED
   │              │
   └──────────────┴───────────────────────→ CANCELED（仅 PENDING 可取消）
```

> [!NOTE]
> LLM 三个维度（script/rhythm/packaging）可独立失败。若至少一个维度成功且核心产物可用，任务状态仍可置为 `COMPLETED`，并在结果中通过 `partialFailedDimensions` 暴露失败维度。

> [!NOTE]
> 每个阶段通过 Redis 存储任务进度百分比和当前步骤描述，前端可实时查询。

## 1.5 统一响应与异常约定

**统一响应结构：**
```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "timestamp": 1716220000000
}
```

**异常分级：**
- `400` 参数校验失败（如视频格式不支持）
- `404` 资源不存在（如模板/任务 ID 不存在）
- `422` 业务逻辑异常（如素材不足无法迁移）
- `500` 系统内部错误（FFmpeg 崩溃、LLM 超时等）
- `503` 服务繁忙（队列积压）

## 1.6 技术扩展点

> [!TIP]
> 以下设计点为开发预留了灵活空间，开发者可根据实际情况选择实现策略。

1. **Engine 可插拔**：每个 Engine 定义接口，便于后续替换实现（如换 LLM 供应商）
2. **消息队列可降级**：开发阶段可通过 `@Async` 线程池替代 RabbitMQ，降低本地开发门槛
3. **文件存储可升级**：当前本地 `/data`，后续可无缝切换到 OSS，只需替换 Infrastructure 层实现
4. **LLM 调用链可观测**：建议在 LlmClient 中埋入日志，记录每次 prompt/response 便于调试
5. **向量能力可插拔**：通过 `Spring AI + Chroma + Ollama Embedding` 建立统一向量基础设施，后续可替换为 Milvus/PGVector 等实现
