# 批次 3：结构模板与知识库模块（v2 — 自适应动态发现）

## 3.1 模块职责

- 定义视频结构的**通用 JSON 模板 Schema v2**，适用于所有品类（含未来未知品类）
- 品类知识库**不再是静态 JSON 文件**，而是 MySQL 动态字典表 + LLM 自主热注册
- 品类扩展字段从"固定对象"升级为**强类型动态 Meta 矩阵**（`dynamicExtensionFields`）
- LLM 发现未知品类时，系统自动捕获、落盘、反哺下一次创作

## 3.2 v1 → v2 核心变更

| 维度 | v1（已废弃） | v2（当前） |
|------|-------------|-----------|
| 品类定义 | 硬编码枚举：`editing` / `marketing` / `motion_graphics` | LLM 自主定性的动态标识符，无白名单限制 |
| 扩展字段 | 每个品类一个固定结构体（`editingStyle`、`sellingStrategy`） | 统一的 `dynamicExtensionFields` KV 矩阵 |
| 知识库存储 | 本地 JSON 文件 `/data/knowledge-base/categories/*.json` | MySQL `category_knowledge` 字典表 |
| 新品类处理 | 降级到最近似品类 or 报错 | 自动热注册 + 沉淀 promptOverrides |
| Prompt 管理 | 品类文件里的 `promptOverrides` | DB 存储 + LLM 自主生成新品类的分析策略 |

## 3.6 品类自动发现与热注册流程

```
用户上传未知类型视频
        │
        ▼
FFmpeg + ASR 完成基础拆解
        │
        ▼
LLM StructureAnalyzer 综合分析
        │
        ├── 尝试匹配已知品类（查 DB category_knowledge 表）
        │       │
        │       ├── 匹配成功 ──► 加载已有 promptOverrides + 种子扩展字段
        │       │                   合并 LLM 本次新发现的字段（增量更新）
        │       │
        │       └── 匹配失败 ──► LLM 自主定性，创建新 category
        │                           │
        ▼                           ▼
LLM 返回完整模板 JSON           触发热注册流程
(含 dynamicExtensionFields)          │
        │                           ▼
        │                   KnowledgeBaseManager
        │                   检测 category 是否存在
        │                           │
        │                    ┌──────┴──────┐
        │                    │ 不存在      │ 存在
        │                    ▼             ▼
        │              INSERT 新品类    UPDATE 增量合并
        │              记录到 DB       新发现的字段
        │                    │             │
        │                    └──────┬──────┘
        │                           │
        ▼                           ▼
   模板持久化              品类知识库完成进化
        │                           │
        └───────────────────────────┘
                    │
                    ▼
        下一次同品类视频分析时
        自动加载已沉淀的 promptOverrides
        实现系统自闭环进化
```

### 3.6.1 热注册核心逻辑（伪代码）

```java
public void persistTemplateAndEvolveKnowledge(VideoStructureTemplate template) {
    String categoryId = template.getCategory();
    CategoryExtensions ext = template.getCategoryExtensions();

    if (!categoryKnowledgeService.exists(categoryId)) {
        // ═══ 全自动发现：注册从未见过的新品类 ═══
        CategoryKnowledgeEntity newCategory = new CategoryKnowledgeEntity();
        newCategory.setCategoryId(categoryId);
        newCategory.setCategoryName(ext.getDiscoveredCategoryName());
        newCategory.setDynamicFields(JSON.toJSONString(ext.getDynamicExtensionFields()));
        newCategory.setPromptOverrides(JSON.toJSONString(ext.getDiscoveredPromptOverrides()));
        newCategory.setDiscoveredByLlm(true);       // 标记为 LLM 自动发现
        newCategory.setConfidenceScore(0.6);         // 初始置信度，随使用次数提升
        newCategory.setUsageCount(1);

        categoryKnowledgeService.save(newCategory);
        log.info("[知识库进化] 自动注册新品类: {} ({})", categoryId, ext.getDiscoveredCategoryName());

    } else {
        // ═══ 增量进化：合并新发现的字段到已有品类 ═══
        CategoryKnowledgeEntity existing = categoryKnowledgeService.getById(categoryId);
        List<DynamicField> existingFields = JSON.parseArray(existing.getDynamicFields(), DynamicField.class);
        List<DynamicField> newFields = ext.getDynamicExtensionFields();

        for (DynamicField newField : newFields) {
            boolean alreadyExists = existingFields.stream()
                .anyMatch(f -> f.getFieldName().equals(newField.getFieldName()));
            if (!alreadyExists) {
                existingFields.add(newField);
                log.info("[知识库进化] 品类 {} 新增扩展字段: {}", categoryId, newField.getFieldName());
            }
        }

        existing.setDynamicFields(JSON.toJSONString(existingFields));
        existing.setUsageCount(existing.getUsageCount() + 1);
        // 使用次数越多，置信度越高（上限 0.95）
        existing.setConfidenceScore(Math.min(0.95,
            0.6 + existing.getUsageCount() * 0.05));

        categoryKnowledgeService.updateById(existing);
    }

    // 持久化模板本身
    templateService.save(template);
}
```

### 3.6.2 品类知识反哺——下次分析时的 Prompt 注入

```java
public String buildAnalysisPrompt(String basePrompt, String categoryId) {
    if (categoryKnowledgeService.exists(categoryId)) {
        CategoryKnowledgeEntity kb = categoryKnowledgeService.getById(categoryId);
        Map<String, String> overrides = JSON.parseObject(kb.getPromptOverrides(), Map.class);

        // 将沉淀的品类分析策略动态注入 Prompt
        String categoryContext = String.format(
            "\n\n[品类上下文] 当前视频属于「%s」品类（置信度 %.0f%%，历史分析 %d 次）。\n" +
            "品类专属分析要求：%s\n" +
            "品类已知特征字段：%s",
            kb.getCategoryName(),
            kb.getConfidenceScore() * 100,
            kb.getUsageCount(),
            overrides.getOrDefault("scriptAnalysis", "无特殊要求"),
            kb.getDynamicFields()
        );

        return basePrompt + categoryContext;
    }

    // 未知品类：让 LLM 自由发挥定性
    return basePrompt + "\n\n[品类发现模式] 该视频品类未知，请自主判断其品类特征，" +
        "创建新的 category ID 和 discoveredCategoryName，" +
        "并在 dynamicExtensionFields 中注入你发现的品类专属特征。";
}
```

## 3.8 多样例模板融合策略

当用户上传多条样例视频时，融合流程不变，但品类处理升级：

```
样例A拆解 ──┐
            ├──► LLM 融合分析
样例B拆解 ──┘         │
                      ├── 两条属于同一品类 ──► 合并字段取并集 + 数值取均值
                      │
                      └── 两条属于不同品类 ──► LLM 自主创建"混合品类"
                                                   如 "editing_x_marketing"
                                                   dynamicExtensionFields
                                                   取两个品类的并集
```

## 3.9 系统进化追踪

每个品类在 DB 中记录进化轨迹：

| 字段 | 说明 |
|------|------|
| `usageCount` | 该品类被使用的次数 |
| `confidenceScore` | 置信度（0.6 起步，随使用增长，上限 0.95） |
| `discoveredByLlm` | 是否为 LLM 自动发现（vs 人工预置种子） |
| `lastEvolvedAt` | 最近一次新增扩展字段的时间 |
| `fieldHistory` | 扩展字段变更记录（可选，JSON 数组记录每次新增） |

## 3.10 开发者扩展点

1. **种子数据初始化**：在 Spring Boot 启动时通过 `CommandLineRunner` 检查并灌入 3 条种子品类数据
2. **品类相似度匹配**：LLM 判定品类时，可先给出已有品类列表让其判断是否属于已知品类，降低重复注册
3. **人工审核机制**：LLM 自动发现的品类可标记为 `pending_review`，运营人员审核后提升为正式品类
4. **字段冲突处理**：增量合并时若同名字段值不同，可保留版本历史或取最新值
5. **品类合并/拆分**：当发现两个品类高度相似时，支持手动合并；反之支持拆分
