# RedStVE 项目 AI 辅助开发工具使用报告

本文档旨在梳理并公示在 **RedStVE (Red Structure Video Engine)** 项目开发生命周期中，我们所引入的 AI 辅助开发工具栈、具体的应用场景，以及明确划分的人机协同边界（即哪些核心逻辑为自主设计，哪些具体实现由 AI 辅助）。

## 一、 AI 工具栈概览

在本项目中，我们采用了多模型协同的现代 AI 编程模式，主要深度使用了以下 AI 开发工具：

1. **Google Gemini (包含 Antigravity IDE)**
2. **Anthropic Claude Code**
3. **OpenAI Codex**
4. **DeepSeek**

## 二、 人机协同开发模式详解

项目采用了**“人工主导架构设计与决策，AI 辅助代码落地与敏捷迭代”**的研发理念。以下是各个环节的具体协作工作流：

### 1. 产品原型与前端可视化
- **自主设计（人工主导）**：项目初期的产品原型图（UI 布局、用户交互流程、多模态拆解看板）均由人工自主手绘与构思。
- **AI 辅助（Gemini）**：基于人工手绘的原型与需求描述，由 **Gemini** 负责编写 React 前端组件、还原 CSS 布局样式，完成了从手绘原型到高保真可视化控制台的快速代码转化。

### 2. 系统架构与链路编排
- **自主设计（人工主导）**：系统最核心的运转骨架——“拆解链路 -> 资产重组 -> 动态策略自进化”的宏观执行顺序，以及 Spring Boot 的模块划分，完全由人工自主设计。
- **AI 辅助（Claude）**：人工将设计的执行顺序草案提供给 **Claude** 进行系统级推演。Claude 主要担任“资深架构顾问”角色，负责对粗略方案进行技术可行性评审，指出潜在的工程难点（如并发渲染、FFmpeg 滤镜冲突等），给出技术栈选型建议。方案的最终可行性裁定与采纳由人工审核拍板。

### 3. Agent 交互协议与 Prompt 工程
- **自主设计（人工主导）**：系统核心的大模型交互“大协议”（如 `video-structure-template`、`slot-match-result` 等）的拆解方向、字段层级关系均由人工统筹设计初版。
- **AI 辅助（多模型综合）**：在确立了协议骨架后，人工根据真实的视频拆解案例与生成效果，利用各类 AI 工具进行反复对弈调试；AI 被高频用于穷举、发散和补全新增字段（例如丰富 Remotion 的 `params` 组件参数白名单、演化品类特征阈值等），极大地提高了协议的完备性。

### 4. 业务逻辑落地与代码编写
- **AI 辅助（Codex / Gemini / DeepSeek）**：在微观工程层面，具体的业务类实现、FFmpeg 复杂的执行器（Executor）逻辑、数据库 CRUD 操作以及工具类的构建，均交由 **Codex**、**Gemini** 和 **DeepSeek** 等大模型负责代码落地。
- **自主测试与把控（人工主导）**：人工团队不盲从 AI 的输出，专门负责业务逻辑的黑盒/白盒测试、边界异常处理、服务联调，以及最终视觉效果的审查与调优。

### 5. 典型案例解析：Chroma 自进化知识库
为了更清晰地说明上述协同模式，以本项目核心的**“品类知识自进化机制”**为例：
- **核心 Idea 提出（人工主导）**：引入 ChromaDB 作为 RAG 向量检索层以实现知识库“越用越聪明”、以及使用动态 JSON 字段（`dynamic_fields`）而非固定表结构来存储品类特征——这套底层创新架构思想**完全由人工团队构思并设计**。
- **补全与落地（AI 辅助）**：在确立了动态 JSON 和向量库的大方向后，AI 工具在此过程中起到了关键的**“Idea 补全优化”**与**“实际代码落地”**作用。例如：AI 辅助推演完善了具体的 `fieldName`、`fieldType`、`allowedValues` 的 Schema 防护结构；Codex 等编程助手则负责落笔编写了 `StructureAnalyzerServiceImpl` 中复杂的数据清洗逻辑与 ChromaDB SDK 的集成代码。

---

## 三、 协作边界总结

在 RedStVE 项目中，**“大脑”始终是人工开发者**。项目的底层创新点、系统架构脉络、核心技术选型及人机交互体验均是人工团队自主思考的结晶；
而 **AI 辅助工具则作为极致高效的“手”和“外脑验证器”**，接管了繁重的机械代码编写、协议字段填充以及方案的穷举验证。这种分工实现了业务洞察力与执行生产力的完美结合。
